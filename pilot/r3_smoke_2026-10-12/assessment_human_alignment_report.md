# R3 Progressive Pilot：机器 Assessment 与人工 Weakness 对照报告

## 1. 报告定位

本报告对 2026-10-12 完成的三篇真实论文 Progressive Pilot 做事后人工对照。
分析对象是 R3 Agent 产生的 21 条 assessment，以及 `sea_selected` 中保存的正式
审稿意见。目的不是计算 precision 或 recall，而是回答三个更基础的问题：

1. Agent 是否抓住了人工评审真正关心的实验设计问题；
2. Agent 与人工使用相似术语时，是否建立了相同的缺陷因果链；
3. 引文校验和 Verifier 是否把合理怀疑收敛到了证据允许的状态。

本报告是 post-hoc qualitative analysis，不属于运行前冻结协议。三篇论文已经参与
开发分析，后续不得作为未见过的最终测试集。

## 2. 比对口径

只有满足以下条件时，才称为“直接相符”：机器和人工指向同一个论文 claim、同一项
实验操作或缺失信息，并认为它会造成相同的解释风险。仅仅同属“评价不充分”或都提到
“baseline”，不算直接相符。

本报告使用五类描述：

- **直接相符**：具体对象和失效路径一致，当前文本中仍有未解决疑问；
- **语义相符但证据失败**：方向与人工相同，但机器 quote、行号或证据对象未通过契约；
- **历史相符但当前已补充**：人工意见对应较早版本，当前 MMD 已出现相关补充材料；
- **部分相符**：关注同一实验区域，但具体主张、机制或因果后果不同；
- **无直接对应**：人工 weakness 没有支持机器提出的具体问题。

人工 review 不是完备真值。没有人工对应不能证明机器判断错误；人工评审也可能遗漏
问题。反过来，人工曾经提出某问题，也不能证明该问题在当前版本仍然存在。尤其是
`I1quoTXZzc`，当前 MMD 包含消融、敏感性、背景迁移、泄漏和 RandInt 解释等补充内容，
而 JSON 中保留的是评审阶段意见。

此外，“通过”被分为三层：Skill 初始输出、确定性 quote/位置校验、Verifier 后的最终
状态。只有后两层均成立，assessment 才是当前系统认可的证据包。

## 3. 跨论文主要发现

### 3.1 Agent 有信号，但信号集中在少数机制

21 条 assessment 的定性映射如下。数字只描述本次样本，不是效果指标。

| 映射类别 | 数量 | 含义 |
|---|---:|---|
| 直接相符且证据有效 | 4 | 机器抓住了人工也明确指出的当前问题 |
| 语义直接相符但证据失败 | 1 | 科学方向正确，quote/位置契约失败 |
| 历史相符但当前已补充 | 1 | 机器触及旧版问题，当前文本已有应对 |
| 部分相符 | 9 | 主题相近，但具体因果链或结论强度不同 |
| 无直接对应 | 5 | 属于机器新增假设，未获人工意见支持 |
| 合理的 `not_applicable` | 1 | Skill 正确识别机制不适用 |

四条最清楚的直接相符 assessment 是：

- `2CxkRDMIG4/b0183afe`：四个小数据集不足以支撑宽泛的不平衡数据泛化；
- `UyNXMqnN3c/dcf59a8f`：30/15 个评测样本的来源和代表性不足；
- `I1quoTXZzc/e1fdd984`：ProbCBM 外部结果与本地多次运行的协议等价性不清；
- `I1quoTXZzc/eba52d50`：外部 best result 与本地 mean/std 的汇总方式不对称。

这四条集中在“评测样本能否代表 claim”和“基线结果是否同协议可比”。这两类问题
具有明确的可观察程序事实，因此最容易形成稳定的人机一致。

### 3.2 引文有效性和科学相关性是两个独立维度

本次 21 条中有 9 条未通过确定性证据校验。部分失败条目其实触及了人工明确提出的
问题。例如 `2CxkRDMIG4/b2f7a2cf` 质疑为什么只报告 precision/recall 而没有 F1，
与人工意见高度一致，但 quote/位置不合格，因此不能成为可接受 finding。

这说明当前瓶颈不只是“模型能否想到问题”。系统还必须把想到的问题绑定到可靠、可
复核的文内证据。一个科学方向正确但无法定位原文的 assessment，在科研审查中仍然是
失败输出。

### 3.3 Verifier 的主要价值是阻止结论升级，但仍可能接受错误的因果方向

Verifier 将多条 `confirmed_flaw` 或 `plausible_risk` 降为
`insufficient_evidence`。典型例子是 DreamGaussian 的 CLIP 指标：CLIP 相似度确实
不直接测量几何保真度，但论文还提供用户研究和定性结果，因此不能据此确认全部质量
结论失效。该 downgrade 合理。

唯一最终保留的 `confirmed_flaw` 是 `I1quoTXZzc/5d869215`：CEM 使用 RandInt，
ECBM 没有使用。它与人工评审关于 RandInt 和 CEM 干预结果的提问有主题交集，但机器
的定性过强。论文同时说明 RandInt 用于提升 CEM 的干预准确率，因此只给 CEM 使用它，
可能使比较更有利于 CEM。该设置确实不是同协议比较，却不能自动证明 ECBM 的优势被
夸大。更稳妥的状态应是 `plausible_risk` 或 `insufficient_evidence`，并要求报告两种
方法在统一干预协议下的结果。

这暴露了当前 Verifier 的一个实质缺口：它会检查“是否存在程序不对称”，但没有稳定
检查“不对称究竟偏向谁”。缺陷确认不仅需要发现 confound，还需要判断 confound 对
目标 claim 的方向和可能后果。

### 3.4 版本差异会制造伪漏检和伪命中

`I1quoTXZzc/34f6146d` 与人工提出的“缺少 single-branch ablation”和“缺少超参数
敏感性分析”直接对应。然而当前 MMD 已包含 Table 4 单分支消融和 Table 5 敏感性
分析。机器最终拒绝该 assessment，反而符合当前版本。

如果把人工 JSON 直接当作当前 MMD 的金标准，这一条会被错误计为 false negative；
如果仅按关键词认为机器命中，又会把已修复问题错误计为 true positive。后续数据集必须
把 review 对应的 manuscript version 一并冻结，或者显式标注
`raised_in_review`、`addressed_in_revision` 和 `still_unresolved`。

### 3.5 当前 taxonomy 存在可解释的边界重叠

`I1quoTXZzc/e1fdd984` 被 Sampling/Split Skill 输出，但其核心是外部 ProbCBM 结果
与本地实验是否可比，更接近 Baseline Fairness。类似地，“leakage”在人工意见中可能
指 CBM 学到概念无关信息，而 FM-R3-01 定义的是测试信息进入训练或模型选择。二者名字
相近，失效机制完全不同。

当前五类仍可作为实验边界，但需要在标注协议中规定主机制和次机制，并依据因果链归类，
不能依赖关键词或由哪个 Skill 先发现来决定标签。

## 4. 分论文分析

### 4.1 `2CxkRDMIG4`：抓住实验覆盖不足，尚未覆盖论文最核心的创新性质疑

人工评审的中心判断不是数据泄漏，而是贡献过于直接、实验规模小、数据并不高度不平衡、
没有系统改变不平衡率、缺少 F1 和 local reject option 等比较。

机器最成功的是 `b0183afe`。它把“四个小数据集”连接到论文对不平衡和真实医疗场景的
宽泛结论，并保持 `insufficient_evidence`，与人工批评的对象和后果一致。

`b2f7a2cf` 也找到了 F1/联合指标问题，却因证据对象失败被拒绝。`9a146838` 对旧 ARC
结果复用的担忧有方法学价值，但人工没有提出这一具体程序问题，只能算部分相符。
`fa7e9983` 关于 fold 内预处理和阈值选择是合理的新增核查项，却没有人工证据支持。

`da9a1721` 将控制消融判为 `not_applicable` 是本篇最清楚的正确弃权。论文提出的是
评价曲线，不是模型组件带来的性能增益，不能因为“没有消融”就机械地产生问题。

因此，本篇说明 Agent 能抓住 R3 范围内的实验代表性和指标选择问题，但无法覆盖创新性、
与标准 PR curve 的理论关系等超出当前五机制的主要拒稿理由。

### 4.2 `UyNXMqnN3c`：对评测样本和指标代理敏感，对领域特定失败模式覆盖不足

人工评审认可 DreamGaussian 的效率贡献，主要担心用户研究规模有限、资源和复杂度披露
不足、text-to-3D 比较较弱、mesh/texture refinement 缺少对照，以及 annealing、纹理
泄漏、饱和和 Janus 等领域特定问题。

`dcf59a8f` 与人工对照最强：机器明确指出 30 个 CLIP 样本和 15 个用户研究样本缺少
采样框架与多样性描述，人工也认为 15 个输入使统计信息有限。状态保持
`insufficient_evidence`，没有把“小样本”自动写成“结果错误”。

`5b8adbdf` 提出的 CLIP 与 3D 几何质量错配是有价值的新增分析，但只有“用户研究规模
有限”这一部分与人工直接重合。Verifier 考虑到用户研究和定性证据后执行 downgrade，
说明反证机制发挥了作用。

其余三条失败 assessment 与人工存在局部交集：`89095428` 涉及 baseline 资源与比较
条件，`3bd0e2bd` 涉及用户研究聚合，`1ca82da0` 涉及组件归因。但它们分别存在引文
错误、从小样本跳到“聚合掩盖失败”的推断、以及把表示变化与内部组件消融混为一体等
问题。

本篇还显示规则型 R3 Skill 的边界：它能检查样本、指标和控制，但难以自然覆盖
non-manifold mesh、纹理饱和、背景颜色泄漏和特定 3D pipeline 对照。这些需要领域知识
或新的机制，不应硬塞进现有五类。

### 4.3 `I1quoTXZzc`：基线公平性命中最好，指标和消融判断最容易过度

人工评价中最强的 R3 批评是 baseline 容量和训练流程不同、外部结果来源不一致、缺少
误差线、部分基线缺失、干预实验覆盖有限，以及复现和超参数信息不足。

`e1fdd984` 和 `eba52d50` 对 ProbCBM 结果来源的分析与人工批评直接相符。前者正确地
保持未知状态；后者从 `confirmed_flaw` 被降级，反映出“存在汇总方式不对称”与“它已经
导致结论错误”之间仍有证据距离。

`5d869215` 捕捉到人工确实追问过的 RandInt 问题，但没有正确处理不对称的方向，因此
不能视为人工确认的 finding。`0fbce111`、`2994052a` 和 `6ff17612` 分别与人工的训练
细节、背景迁移和调参协议疑问部分重合，但没有达到同一具体因果链。

两个 Metric Alignment assessment 与人工对应最弱。`a8bb37bc` 认为 overall concept
accuracy 不能证明 interaction，忽略了论文已有的分支消融和条件解释实验；
`8948c902` 用 class accuracy 不占优反驳总体贡献，却没有充分尊重论文对主要任务的
限定。人工评审中甚至有意见认为 class accuracy 的表现是可预期的。这两条被拒绝是合理
的。

本篇表明 Baseline Fairness 是当前系统最有希望的 Skill，Metric Alignment 则最需要
约束 claim 范围、聚合全部证据并检查替代解释。

## 5. 按 Skill 观察

| Skill | 三篇表现 | 主要问题 |
|---|---|---|
| FM-R3-01 数据泄漏 | 没有直接复现人工 weakness，仅有一条训练细节部分相符 | 容易从“未报告”生成假设；与 concept leakage 名称冲突 |
| FM-R3-02 采样/划分 | 对小样本代表性命中稳定，也发现外部结果来源问题 | 外部 baseline provenance 与 FM-R3-03 重叠 |
| FM-R3-03 基线公平性 | 与人工一致性最强 | 需要判断不对称的方向和对 claim 的实际影响 |
| FM-R3-04 指标匹配 | 能提出有价值的新问题，但过强结论较多 | 容易忽略多源证据、论文限定范围和已有反证 |
| FM-R3-05 控制/消融 | 能正确判定不适用，也能触及人工消融意见 | 对版本变化敏感；容易把“细节未写全”升级为归因失败 |

## 6. 本轮能够支持的结论

本轮可以支持以下有限结论：

1. 完整 Agent 在三篇真实论文上能够提出若干与人工 weakness 具体一致的 R3 问题；
2. 最稳定的人机交集是样本代表性和基线可比性；
3. quote/位置契约拦截了部分语义相关但不可复核的输出；
4. Verifier 通常能压低过强状态，但尚不能稳定判断 confound 的作用方向；
5. 当前人工 JSON 与 MMD 可能存在版本错位，不能直接作为逐条金标准；
6. 三篇均参与了开发分析，不能再用于无偏效果评估。

本轮不能支持“Agent 达到人工评审水平”“Skills 优于一般 Prompt”或任何 precision、
recall 数值。人工 review 并非完备标注，assessment 也不是预先定义的独立样本；把二者
直接计数会同时产生漏标偏差、版本偏差和单位不一致。

## 7. 下一步实验建议

### 7.1 先修复证据闭环

在继续付费跑论文前，应完成以下工程修正：

1. 模型只负责提出证据片段，最终 quote、行号和字符区间由本地 resolver 从 MMD 回填；
2. 支持规范化空白后的候选定位，但保存时必须回填 MMD 中的逐字原文；
3. deterministic-invalid assessment 在调用模型 Verifier 前直接拦截，减少无效请求；
4. 分开报告 candidate、evidence-valid、verifier-accepted 和 final finding；
5. 对每个 Skill 限制候选数，并要求先按 claim 和因果链去重。

这不是 Evidence Detector。它只修复已经选中证据的确定性定位，可以在不引入检索系统的
情况下消除本轮最明显的工程噪声。

### 7.2 修订两条关键判定规则

Baseline Fairness 增加“方向性检查”：明确 procedure asymmetry 更可能有利于 proposed
method、baseline，还是方向未知。只有能够连接到目标 claim 的不利后果时，才能进入
`confirmed_flaw`。

Metric Alignment 增加“证据集合检查”：在判定某指标不能支撑 claim 前，必须列出论文
用于支持该 claim 的全部主要证据，包括用户研究、定性结果、其他指标和明确的 scope
限定。单一指标不是完整证据集时，不得确认整体 claim 失效。

### 7.3 建立版本一致的人工标注协议

下一批论文应保存精确版本，并以 claim 为单位标注：

- claim 和适用机制；
- supporting evidence 与 counterevidence；
- 人工状态及理由；
- weakness 是当前仍存在、已在 rebuttal 解决，还是无法从文本判定；
- 主机制和允许的次机制；
- 两位标注者及仲裁结果。

人工 reviewer 原文可作为候选来源，但不能直接作为金标准。标注者必须重新对照 Agent
实际读取的同版本 MMD。

### 7.4 先做小型条件实验，再决定样本量

建议选 6 篇从未参与开发、长度分层的新论文，运行四个冻结条件：

1. general review；
2. static R3 checklist；
3. progressive Skills，不使用 Verifier；
4. progressive Skills，加 Verifier。

六篇乘四条件共 24 次运行，只用于估计方差、成本和标注负担，并验证比较流程。主要
结果应是 claim-level supported-weakness precision、人工 R3 concern coverage、无证据
指控率、证据定位正确率、状态校准、每篇 token 和延迟。`insufficient_evidence` 应单独
评价为合理弃权或无效泛化，不能简单计为正例或负例。

完成这 24 次运行后，再用观察到的差异和方差决定正式实验需要多少论文。直接预设一个
较大的论文数，既可能浪费 API 成本，也可能仍然没有足够统计功效。

### 7.5 保留三篇作为开发回归集

后续修改后可重跑这三篇，但用途应限于回归测试：

- F1 问题能否在证据有效的情况下重现；
- RandInt 不再被错误升级为确定缺陷；
- 已存在的消融不会再次被判为缺失；
- CLIP 指标判断能否综合用户研究与定性证据；
- 外部 baseline 结果能否稳定归入 FM-R3-03 或输出清楚的多机制标签。

这组回归测试能验证已知故障是否修复，但其结果不能进入正式效果统计。
